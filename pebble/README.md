# Wafflelist for Pebble

A Pebble watchapp for [Wafflelist](../README.md) showing the **Inbox** view.

- **Select** on the top row (`+ New todo`) adds a todo using the watch's
  native dictation.
- **Double-press Select** on a todo marks it done.
- **Long-press Select** refreshes the list.

## How it works with end-to-end encryption

Wafflelist is E2E-encrypted (AES-256-GCM blobs, Ed25519-signed requests),
and the watch can't do that crypto. So the split is:

- **Watch (C, `src/c/wafflelist.c`)** - only displays plaintext titles and
  sends user actions (`AddTodo`, `Complete`, `Request`) over AppMessage.
- **Phone (PebbleKit JS, `src/pkjs/`)** - holds the derived keys and does
  everything else: fetching/decrypting todos, encrypting new blobs, and
  Ed25519-signing every API request, mirroring the web client
  (`src/lib/crypto.ts`, `src/lib/stores/todos.ts`) exactly.

PebbleKit JS has no WebCrypto, so `src/pkjs/crypto.js` is a pure-JS
implementation of SHA-256/512, HMAC, PBKDF2, HKDF, AES-256-GCM and Ed25519
(the latter derived from TweetNaCl.js). It is verified byte-for-byte
against Node's WebCrypto by the test suite, including a full interop test
of the Wafflelist key-derivation and blob/signature formats.

## Setup

1. Install the app, then open its **Settings** in the Pebble phone app.
2. Enter your 12-word seed phrase (and server URL if self-hosting) and
   press Save.

The phrase is checksum-validated, used once to derive your keys (PBKDF2
600k iterations runs in chunks for a few seconds - the watch shows
progress), and then discarded. Only the derived keys are stored, in the
phone app's localStorage. The watch stores nothing.

## Building

Requires the [Pebble SDK](https://developer.repebble.com/sdk/):

```sh
cd pebble
pebble build
pebble install --phone <phone-ip>
```

Targets `basalt`, `chalk`, `diorite` and `emery` (platforms with a
microphone; `aplite` has none, so it is excluded).

## Tests

```sh
cd pebble
node test/crypto.test.cjs   # crypto vs Node WebCrypto, incl. web-client interop
node test/app.test.cjs      # phone-side logic vs a mocked Pebble + Wafflelist server
```

## Files

- `src/c/wafflelist.c` - watchapp UI (MenuLayer, dictation, AppMessage)
- `src/pkjs/index.js` - phone-side logic (config page, API, sync)
- `src/pkjs/crypto.js` - pure-JS crypto primitives
- `src/pkjs/wordlist.js` - BIP39 wordlist (generated by `tools/gen-wordlist.cjs`)
- `tools/gen-sha-constants.mjs` - generates the SHA constant tables in crypto.js

## Caveats / not yet done

- Inbox view only; no lists, due dates or snoozing from the watch.
- The config page is served as a `data:` URL; if the mobile app refuses to
  open it, the page needs to be hosted somewhere instead.
- GCM IVs / UUIDs come from a SHA-256 ratchet seeded with timing +
  `Math.random()` (PebbleKit JS has no CSPRNG). IV *uniqueness* - the
  property GCM actually needs - is ensured by counter + timestamp mixing.
- The phone fetches the full todo list on each launch/refresh (no delta
  sync or SSE).
